# Filament Chatbot

Чат с клиентами и визуальный конструктор чат-бота для любой панели Filament.

Переписка из виджета на сайте и из мессенджеров, редактор сценариев на канве,
база знаний и ответы языковой моделью — и всё это без того, чтобы пакет знал
хоть что-нибудь о вашем деле.

> Пакет в разработке. Ниже описано то, что уже есть.

## Требования

PHP 8.3+, Laravel 11/12/13, Filament 5.

## Установка

```bash
composer require mb4it/filament-chatbot
php artisan migrate
```

Плагин добавляется в ту панель, где нужны экраны чата:

```php
use MB\FilamentChatbot\ChatbotPlugin;

return $panel->plugins([ChatbotPlugin::make()]);
```

## Посмотреть за минуту

```bash
php artisan chatbot:demo-data
php artisan chatbot:demo "my printer is broken" "Alex" "alex@example.test" "it will not switch on" "today"
```

Первая команда заводит бота, шесть сценариев на все виды узлов, десять тем
базы знаний и заготовки ответов оператора. Вторая проигрывает разговор и печатает
расшифровку вместе с журналом прогона — это самый быстрый способ убедиться, что
пакет вправду подключён к **вашему** приложению, с вашими провайдерами и вашей
базой, а не к тестовому окружению.

## Замысел

Большинство пакетов чат-ботов либо намертво вшивают свою предметную область —
заказы, брони, тикеты, — либо дают язык сценариев и называют это гибкостью.
Здесь небольшой закрытый словарь узлов и **три способа рассказать боту о вашем
приложении**, по возрастанию трудозатрат:

1. **Ресурсы данных** — объявляете модель, одобренные поля и потолок выдачи,
   и бот читает ваши записи. Без кода.
2. **Возможности** — регистрируете действие со схемой входа и обработчиком.
3. **Свой вид узла** — когда первых двух не хватило.

Ни один класс пакета не ссылается на ваши модели. Разговор указывает на ваши
записи нулевыми морфами, которые пакет **никогда не разыменовывает**, а модель
оператора берётся из вашей настройки аутентификации.

## Свой узел — один класс

Обязательны только `key()`, `label()` и `run()`. Форма настроек в редакторе
рисуется по `fields()`, поэтому **ни строчки JavaScript и никакой пересборки**.

```php
final class AwardPointsStep extends StepType
{
    public static function key(): string { return 'shop.award_points'; }

    public function label(): string { return 'Начислить баллы'; }

    public function outputs(): StepOutputs { return StepOutputs::Pair; }

    public function fields(): array
    {
        return [
            Field::number('points')->label('Сколько')->default(50)->min(1),
            Field::variable('into')->label('Новый баланс записать как'),
        ];
    }

    public function run(StepContext $context): StepResult
    {
        $customer = $context->conversation->contact;

        if ($customer === null) {
            return StepResult::second()->traced(RunStep::FAILED, ['reason' => 'некому начислять']);
        }

        $balance = $customer->award((int) $context->setting('points', 0));
        $context->runtime->store((string) $context->setting('into', 'points'), (string) $balance);

        return StepResult::next()->traced(RunStep::PASSED, ['balance' => $balance]);
    }
}
```

```php
Chatbot::registerStep(AwardPointsStep::class);
```

Ключи узлов префиксуйте. `shop.award_points` у выпущенного сценария не отберёт
никакой будущий пакет, а `award_points` — вполне.

**Узел, который спрашивает, входится дважды**: `run()` задаёт вопрос и возвращает
`StepResult::wait()`, а `resume()` получает ответ следующим ходом. Это не флаг
внутри одного метода — узел, повторно вошедший после возобновлённой паузы или
повторной доставки вебхука, иначе не отличит «мне ответили» от «я снова здесь»
и задаст тот же вопрос второй раз.

## Что уже работает

Двадцать один вид узла. Стоит знать про два:

- **`call` и `result`** — вызов подсценария **с возвратом значения**. Общая
  работа (узнать, кто человек; собрать телефон) пишется один раз отдельным
  сценарием и зовётся откуда угодно, вместо того чтобы копироваться в каждый
  и расходиться копиями;
- **`choose`** — показать человеку **его собственные** записи кнопками и
  запомнить выбранную. Универсальная замена узлам вида «выбрать бронь», которые
  иначе пришлось бы писать под каждый проект.

Плюс `query` (чтение ресурса данных), `action` (действие хоста), `http` по белому
списку доменов, `approval`, `for_each` с обязательным конечным пределом,
`transform`, `answer`, `ai`.

**Два правила выпуска, которые дороже любого узла:** запись достижима только
через узел подтверждения, а цикл без конечного предела не выпускается. Сценарий,
нарушающий любое из них, просто не публикуется — и это последний момент, когда
такой изъян стоит дёшево.

## ИИ

Выключен по умолчанию, и **каждый сценарий обязан работать без него**: не задан
ключ, отказал провайдер, исчерпан бюджет — все эти случаи идут одной веткой
«не смог».

Драйверы: `null` (умолчание), `openai` (любой OpenAI-совместимый адрес — OpenRouter,
Ollama, LM Studio, Azure, DeepSeek, локальный vLLM) поверх `Http` и ничего больше,
`laravel-ai` (когда `laravel/ai` установлен) и **ваш собственный**.

`laravel/ai` намеренно в `suggest`, а не в `require`: он всё ещё 0.x, тянет
`aws/aws-sdk-php` целиком и поднял бы нижнюю планку до Laravel 12.62 — каждому,
кто поставит этот пакет, включая тех, кто ходит в один-единственный адрес.

## Виджет для сайта

```html
<script src="https://app.example.com/chatbot/widget.js" async data-bot="support"></script>
```

Один файл, без сборки и зависимостей. **Не доверяет странице, на которой стоит**:
кто человек — решает подпись, выданная вашим приложением. И не отвечает сайту,
которого нет в `chatbot.widget.origins`; пустой список запрещает всем, а не
разрешает всем — иначе одна забытая настройка превращается в точку, которую
может встроить кто угодно и оплачивать её вашим бюджетом модели.

## Разработка

Пакет разрабатывается против пустого приложения Filament в `workbench/`, где нет
ни одного класса пакета — только та регистрация, которую написал бы хост. Если
экрану нужно что-то, чего в стенде нет, значит это то, на что хост наткнётся
в первый же день.

```bash
composer test
composer serve   # стенд на /admin
```
